# 헤이 치즈! — Mini-game Prototype & Validation

> **Project:** &lt;Hey Cheese!&gt;  
> **Role:** Mini-game Client Programmer  
> **Contribution:** 4종 미니게임 로직 구현 및 Android·사용자 테스트 환경에서 기능 검증

> **Common Flow · Game-specific Rules · Android Validation**

## 1. 문서 목적

서로 다른 규칙을 가진 4종 미니게임의 입력, 상태, 완료 조건과 피드백을 구현하고 Android·사용자 테스트 환경에서 검증한 과정을 정리합니다.

---

## 2. 담당 기능

- 숨바꼭질 미니게임
- 음식 선택 / 식탁 정리 미니게임
- 달리기 미니게임
- 몰래 춤추기 미니게임

---

## 3. 설계 목표

- 미니게임의 시작·완료·재시작·복귀 흐름을 일관되게 관리
- 각 게임의 입력 방식과 완료 조건은 독립적으로 유지
- 사용자의 입력 결과를 UI와 오브젝트 상태에 즉시 반영
- 제한 시간과 단계별 진행 순서를 명확히 제어
- 실제 Android 환경에서 터치와 완료 흐름 검증

---

## 4. 공통 흐름

```text
미니게임 진입
→ 상태 초기화
→ 목표·UI 표시
→ 사용자 입력 처리
→ 진행 상태 갱신
→ 완료 조건 판정
→ 결과 피드백
→ 재시작 또는 메인 스토리 복귀
```

---

## 5. 핵심 구현

### 5.1 MiniGameManager

미니게임의 공통 시작, 완료와 메인 흐름 복귀를 관리합니다. 개별 Manager는 각 게임의 입력·조건·연출을 담당합니다.

### 5.2 상태 기반 조건 판정

List와 Dictionary로 선택·작업 상태를 관리하고, 모든 조건을 만족한 경우에만 완료 상태로 전환했습니다.

### 5.3 Coroutine 기반 시간 흐름

카운트다운, 제한 시간, 이동과 랜덤 방해 이벤트를 Coroutine으로 분리해 순차 처리했습니다.

### 5.4 UI 피드백

Slider, Text와 Sprite를 사용해 현재 진행도, 남은 시간과 결과를 표시했습니다.

### 5.5 모바일 입력

터치 시작·유지·종료를 현재 미니게임 상태와 연결하고, 달리기와 진행도 증가 등 게임별 동작을 수행했습니다.

---

## 6. 검증 항목

| 항목 | 확인 내용 |
| --- | --- |
| 상태 초기화 | 재시작 시 이전 진행 상태가 남지 않는가 |
| 입력 | Android 기기에서 터치가 의도한 오브젝트에 전달되는가 |
| 완료 조건 | 일부 조건만 충족한 상태에서 완료되지 않는가 |
| 시간 흐름 | 카운트다운과 제한 시간이 순서대로 동작하는가 |
| UI | 내부 진행도와 화면 표시가 일치하는가 |
| 복귀 | 완료 후 메인 흐름으로 정상 복귀하는가 |
| 반복 조작 | 빠른 입력에서도 상태가 비정상적으로 건너뛰지 않는가 |

## 9. 한계 및 개선 방향

- 개별 Manager에 입력·상태·UI 책임이 함께 존재할 수 있음
- Coroutine 취소와 중복 실행 정책을 공통화할 필요가 있음
- 미니게임별 자동 테스트와 상태 시각화 도구가 없음

### 개선 방향

- 공통 State Enum과 전환 API 정의
- 입력 처리와 규칙 판정 분리
- CancellationToken 또는 Coroutine Handle 정책 통일
- 미니게임 상태를 확인할 수 있는 Debug Panel
- 목표 사용자 대상 후속 테스트

---

## 10. 게임 프로그래밍 역량

기능을 작은 프로토타입 단위로 구현하고, 공통 요소와 개별 규칙을 분리한 뒤 실제 기기와 사용자 환경에서 검증했습니다. 결과뿐 아니라 테스트의 한계와 후속 개선 과제를 함께 정리했습니다.
